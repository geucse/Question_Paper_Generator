## Course outcomes

- **CO1** — Understand the various phases and fundamental principles of compiler design like lexical, syntactical, semantic analysis, code generation and optimization.
- **CO2** — Compare and contrast various parsing techniques such as SLR, CLR, LALR etc.
- **CO3** — Use annotated tree to design the semantic rules for different aspects of programming language.
- **CO4** — Implement lexical analyzer and parser by using modern tools like Flex and Bison.
- **CO5** — Examine patterns, tokens & regular expressions for solving a problem in the field of data mining.
- **CO6** — Design a compiler for concise programming language.

### Q1

**Short Answer · 5 marks · medium · Understand · CO1 · Unit 1: “The Phases of a Compiler”**

Show the output of each phase of a compiler for the statement position = initial + rate * 60, where all variables are float.


**Model answer:** Lexical: id1 = id2 + id3 * 60. Syntax: tree with = at the root, + over id2 and (* over id3 and 60). Semantic: inttofloat(60) inserted. Intermediate: t1 = inttofloat(60); t2 = id3 * t1; t3 = id2 + t2; id1 = t3. Optimisation: t1 = id3 * 60.0; id1 = id2 + t1. Code generation: LDF R2, id3; MULF R2, R2, #60.0; LDF R1, id2; ADDF R1, R1, R2; STF id1, R1.

Which cousin of the compiler handles #include directives and macro expansion before compilation?

- (A) Assembler
- (B) Preprocessor
- (C) Linker
- (D) Loader

**Model answer:** The preprocessor processes directives and expands macros.

### Q3

**Numerical · 2 marks · easy · Apply · CO5 · Unit 1: “Recognition of Tokens”**

How many tokens does a C lexical analyser produce for the statement: if (x >= 10) y = x * 2;


**Answer:** 12

**Model answer:** if, (, x, >=, 10, ), y, =, x, *, 2, ; = 12 tokens.

### Q4

**Short Answer · 3 marks · medium · Understand · CO1 · Unit 1: “Input Buffering”**

Explain the two-buffer input scheme with sentinels and why it speeds up lexical analysis.


**Model answer:** Input is read into two halves alternately; the lexeme-begin and forward pointers move through them. A sentinel (eof) at the end of each half means only one test per character is needed instead of separate end-of-buffer and end-of-file checks.

### Q5

**Long Answer · 8 marks · hard · Apply · CO2 · Unit 2: “Top-down Parsing”**

For the grammar E -> TE', E' -> +TE' | e, T -> FT', T' -> *FT' | e, F -> (E) | id, compute FIRST and FOLLOW of every non-terminal and fill the LL(1) table entries for E' and T'.


**Model answer:** FIRST(E) = FIRST(T) = FIRST(F) = {(, id}; FIRST(E') = {+, e}; FIRST(T') = {*, e}. FOLLOW(E) = FOLLOW(E') = {), $}; FOLLOW(T) = FOLLOW(T') = {+, ), $}; FOLLOW(F) = {*, +, ), $}. M[E', +] = E' -> +TE'; M[E', )] = M[E', $] = E' -> e. M[T', *] = T' -> *FT'; M[T', +] = M[T', )] = M[T', $] = T' -> e.

### Q6

**Short Answer · 4 marks · medium · Analyze · CO2 · Unit 2: “LR Parsers”**

Compare SLR, canonical LR(1) and LALR parsers in terms of the grammars they accept and the size of their parsing tables. Which is used by parser generators such as Yacc, and why?


**Model answer:** Power: SLR < LALR < LR(1). Table size: SLR and LALR have the same number of states (LR(0) items), LR(1) many more. Yacc/Bison use LALR: nearly the power of LR(1) with SLR-sized tables.

### Q7

**True/False · 1 mark · easy · Understand · CO2 · Unit 2: “Operator-Precedence Parsing”**

True or False: An operator-precedence grammar may contain a production whose right side has two adjacent non-terminals.


**Answer:** False

**Model answer:** False. Operator grammars have no e-productions and no two adjacent non-terminals on any right side.

### Q8

**Programming · 6 marks · medium · Apply · CO4 · Unit 2: “Parser Generators”**

Write a Yacc/Bison specification for a calculator that evaluates expressions with integers, +, *, and parentheses, giving * higher precedence than +.

*Language:* Yacc

**Model answer:**

```yacc
%token NUM
%left '+'
%left '*'
%%
line : expr '\n' { printf("%d\n", $1); } ;
expr : expr '+' expr { $$ = $1 + $3; }
     | expr '*' expr { $$ = $1 * $3; }
     | '(' expr ')'  { $$ = $2; }
     | NUM ;
%%
```

### Q9

**Short Answer · 4 marks · medium · Apply · CO3 · Unit 3: “Syntax-Directed definitions”**

Using the S-attributed definition E -> E1 + T {E.val = E1.val + T.val}, E -> T, T -> T1 * F {T.val = T1.val * F.val}, T -> F, F -> digit {F.val = digit.lexval}, draw the annotated parse tree for 3 * 5 + 4 and give the value at the root.


**Model answer:** T.val = 3 * 5 = 15 on the left; T for 4 has val 4; E.val = 15 + 4 = 19 at the root. Attributes are computed bottom-up.

### Q10

**Assertion-Reason · 2 marks · medium · Understand · CO3 · Unit 3: “L-attributed definitions”**

Read the assertion and reason about L-attributed definitions and choose the correct option.

- **Assertion (A):** Every S-attributed definition is also L-attributed.
- **Reason (R):** An S-attributed definition uses only synthesized attributes, which an L-attributed definition always allows.
- (A) Both A and R are true, and R is the correct explanation of A
- (B) Both A and R are true, but R is not the correct explanation of A
- (C) A is true, but R is false
- (D) A is false, but R is true

**Answer:** (A) Both A and R are true, and R is the correct explanation of A

**Model answer:** Both true and R explains A.

### Q11

**MCQ · 1 mark · easy · Understand · CO1 · Unit 3: “Storage-allocation strategies”**

Which storage-allocation strategy is required to support recursive procedures?

- (A) Static allocation
- (B) Stack allocation
- (C) Allocation in the code segment
- (D) None; recursion needs no storage

**Answer:** (B) Stack allocation

**Model answer:** Each activation needs its own record, pushed and popped on the control stack.

### Q12

**Numerical · 3 marks · medium · Analyze · CO1 · Unit 3: “Parameter passing”**

Given void f(int a, int b) { a = a + b; b = a + b; } and int x = 1, y = 2; f(x, y); with both parameters passed by reference, what is the value of x + y after the call?


**Answer:** 8

**Model answer:** a aliases x: x = 1 + 2 = 3; b aliases y: y = 3 + 2 = 5; x + y = 8 (by value it would stay 3).

### Q13

**Short Answer · 4 marks · medium · Apply · CO1 · Unit 4: “Intermediate Languages”**

Generate three-address code for a = b * -c + b * -c and represent it as quadruples.


**Model answer:** t1 = minus c; t2 = b * t1; t3 = minus c; t4 = b * t3; t5 = t2 + t4; a = t5. Quadruples (op, arg1, arg2, result): (minus, c, -, t1), (*, b, t1, t2), (minus, c, -, t3), (*, b, t3, t4), (+, t2, t4, t5), (=, t5, -, a).

### Q14

**Numerical · 2 marks · medium · Apply · CO1 · Unit 4: “Basic blocks and Flow graphs”**

How many basic blocks does this code contain? (1) i = 1 (2) t1 = i * 4 (3) a[t1] = 0 (4) i = i + 1 (5) if i <= 10 goto (2) (6) x = 0


**Answer:** 3

**Model answer:** Leaders: (1) first statement, (2) jump target, (6) follows a jump. Blocks: {1}, {2-5}, {6}.

### Q15

**Short Answer · 4 marks · hard · Apply · CO6 · Unit 4: “The dag representation of basic blocks”**

Construct the DAG for the basic block a = b + c; b = a - d; c = b + c; d = a - d, and use it to remove the redundant computation.


**Model answer:** Nodes: n1 = b0 + c0 (a); n2 = n1 - d0 (b, later also d, since a and d are unchanged); n3 = n2 + c0 (c). Optimised block: a = b + c; b = a - d; c = b + c; d = b.

### Q16

**Short Answer · 4 marks · medium · Understand · CO3 · Unit 4: “Back patching”**

Explain how backpatching generates jumping code for boolean expressions in a single pass, using truelist and falselist.


**Model answer:** Jumps are emitted with empty targets and their addresses kept in lists (truelist, falselist). When the target becomes known (e.g. the marker before the next statement), backpatch fills it into every jump on the list; merge combines lists for OR and AND.

### Q17

**MCQ · 1 mark · easy · Understand · CO1 · Unit 5: “Peephole optimization”**

Which of the following is NOT a peephole optimisation?

- (A) Eliminating redundant load and store pairs
- (B) Removing unreachable code after an unconditional jump
- (C) Algebraic simplification such as x = x + 0
- (D) Global register allocation across procedures

**Answer:** (D) Global register allocation across procedures

**Model answer:** Peephole optimisation looks at short windows of target code; global register allocation needs whole-program analysis.

### Q18

**Short Answer · 5 marks · medium · Apply · CO6 · Unit 5: “The principal sources of optimization”**

Optimise the block t1 = 4 * i; x = a[t1]; t2 = 4 * i; y = a[t2]; t3 = t1; z = t3 + 0 by applying common subexpression elimination, copy propagation, algebraic simplification and dead code elimination. Name each step.


**Model answer:** CSE: t2 = t1, so y = a[t1]. Copy propagation: z = t1 + 0. Algebraic simplification: z = t1. Dead code: t2 and t3 are no longer used and are removed. Result: t1 = 4 * i; x = a[t1]; y = a[t1]; z = t1.

### Q19

**Short Answer · 3 marks · medium · Understand · CO1 · Unit 5: “Loops in flow graphs”**

Explain loop-invariant code motion and induction-variable elimination with a short example.


**Model answer:** Code whose operands do not change in the loop (e.g. t = n * 4 inside for i) is moved to the pre-header. Induction variables change by a constant each iteration (i, and j = 4 * i); j can be updated as j = j + 4 and i removed if only used to compute j.

### Q20

**Case Study · 10 marks · hard · Create · CO4, CO6 · Unit 5: “Planning a compiler”**

> **Case:** A university wants a small language for writing fee rules, for example: rule late_fee: if days > 10 then amount = 50 + 5 * (days - 10); Rules must be checked for errors and translated into a stack-based bytecode run by the fee system.

Plan a compiler for the language in the case: describe the phases you would implement, how you would use Flex and Bison, the intermediate representation, and how you would test it.


**Model answer:** Flex for tokens (keywords, identifiers, numbers, operators); Bison grammar with precedence for arithmetic and if-then; semantic checks (declared variables, types); generate three-address code, then stack bytecode (push, add, mul, jump-if-false); simple constant folding. Test with unit tests per phase, valid and invalid rule files, and comparison of outputs with hand-computed fees.
